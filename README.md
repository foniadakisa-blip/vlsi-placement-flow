# VLSI Placement Flow with Time Constraints

Experimental VLSI physical-design placement flow developed for an undergraduate thesis at the **University of Thessaly**.

The repository studies how three different starting-placement paths behave when they are processed by the same custom flow under explicit runtime limits.

<img width="2617" height="681" alt="placement_flow" src="https://github.com/user-attachments/assets/d3f883de-3364-4265-8315-031f367ae083" />

## Overview

The implemented flow is:

**Initial Placement → Global Placement → Legalization → Detailed Placement**

The three starting-placement paths are:

- **ePlace** — external initial `.pl` placement
- **mPL6** — external initial `.pl` placement
- **Pseudo** — custom grid-based initialization

ePlace and mPL6 are **not reimplemented** here. Their placement coordinates are used as input to the same custom Global → Legalization → Detailed pipeline.

The Pseudo path is different: movable-cell coordinates are generated by the custom grid initializer, while fixed terminals are preserved.

The parser uses the following UCLA/Bookshelf files:

- `.aux`
- `.nodes`
- `.nets`
- `.pl`
- `.scl`

The `.wts` file may be referenced by a benchmark `.aux`, but weights are **not used** by the current objective function.

## Quick Start

Benchmark files are **not included** in this repository.

Run the commands from the repository root.

### Global Placement

```powershell
python src/global_placer.py path/to/ibm01.aux --pl path/to/input.pl --time 144 --seed 42 --out global.pl
```

### Legalization

```powershell
python src/legalization.py path/to/ibm01.aux --pl global.pl --time 144 --out legalized.pl
```

### Detailed Placement

```powershell
python src/detail_placer.py path/to/ibm01.aux --pl legalized.pl --time 144 --out detailed.pl
```

### Pseudo Grid Initialization + Global Placement

```powershell
python src/global_placer_grid.py path/to/ibm02.aux --random-time 5 --time 10 --grid-cols 10 --grid-rows 10 --seed 42 --out pseudo_global.pl
```

More examples are available in [`examples/sample_commands.md`](./examples/sample_commands.md).

## Objective Function

The experiments use **center-based HPWL**.

For each net:

```text
HPWL = (max_x - min_x) + (max_y - min_y)
```

where the coordinates correspond to cell centers.

Pin offsets are intentionally not used in the current objective. Therefore, the reported values are internally comparable inside this experimental framework, but they should not be assumed to match native ePlace or mPL6 reports.

## Global Placement

The custom Global Placer performs greedy random pair swaps:

1. choose two movable cells,
2. swap their positions,
3. recompute total HPWL,
4. accept the swap only if HPWL strictly decreases,
5. otherwise revert it.

The stage terminates on either:

- the configured time limit, or
- the configured number of consecutive no-improvement passes.

The current Global implementation recomputes the **full HPWL after every attempted swap**, which is intentionally simple but computationally expensive.

## Legalization

The Legalizer:

- reads legal rows and sites from `.scl`,
- excludes fixed obstacles from available row space,
- considers rows according to distance from the previous `y`,
- uses the previous `x` coordinate as the desired horizontal target,
- snaps cells to legal sites,
- records Manhattan displacement,
- checks movable-cell overlap and row/site violations.

A legalization output is written only when all movable cells are placed and the implemented legality checks pass.

## Detailed Placement

Detailed Placement starts from a legal placement and performs local refinement:

- cells are grouped by row,
- adjacent pairs are tested,
- only nets connected to the two candidate cells are reevaluated,
- a move is accepted only when affected-net HPWL decreases,
- the search stops on time limit or when a full pass finds no accepted move.

## Detailed Placement Comparison

| Path | Improvement | Passes | Swaps kept | Runtime | Termination |
|---|---:|---:|---:|---:|---|
| ePlace | 9,562 | 4 | 1,071 | ≈ 2.8–3.3 s | no improvement |
| mPL6 | 81,202 | 6 | 7,302 | ≈ 4.7–5.4 s | no improvement |
| Pseudo G100 | 99,080 | 5 | 8,185 | 4.576 s | no improvement |

A larger Detailed Placement gain does **not** automatically mean a better overall placement path. In the mPL6 and Pseudo cases, the legalized starting point had more damage available to recover.

## Limitations

This is an academic research prototype rather than a production physical-design tool.

Current limitations include:

- full HPWL recomputation in Global Placement,
- random pair selection in Global Placement,
- center-based HPWL without pin offsets,
- greedy row-based Legalization,
- adjacent-only Detailed Placement,
- limited multi-seed statistical evaluation.

## Future Work

Possible extensions include:

- affected-net HPWL evaluation in Global Placement,
- gain-guided or connectivity-guided swaps,
- displacement-aware objectives,
- wider local windows in Detailed Placement,
- pin-offset-aware HPWL,
- multiple random seeds and statistical analysis,
- density/congestion-aware objectives,
- parallel candidate evaluation.

## Implementation Note

The source code in this repository is a **cleaned/reconstructed research version aligned with the final thesis methodology and recorded experiment logs**. It is not claimed to be byte-for-byte identical to every historical script used during development.

This distinction is important when comparing a newly executed run with the archived thesis results.
